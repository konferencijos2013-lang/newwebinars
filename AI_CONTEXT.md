## Webinar chat scenarios — implemented and deployed

### What is available

A webinar owner can create a reusable scripted chat for automated/recorded webinars:

- Add, edit, activate/deactivate and delete individual script messages.
- Each message has elapsed time (`trigger_seconds`), sender name, sender role, text and source.
- Import messages from the latest **finished** live session. The import calculates elapsed time from the live session start and excludes soft-deleted messages.
- Generate a draft scenario with AI based on webinar title, description, presenter and duration.
- Open the scenario editor from webinar details using the **Chat scenario** button.

### Main implementation

- Editor page: `src/features/webinars/pages/ChatScriptEditorPage.tsx`
- Editor API: `src/features/webinars/api/chatScripts.ts`
- Route: `/webinars/:id/chat-script` in `src/routes/index.tsx`
- Entry point: `src/features/webinars/pages/WebinarDetailPage.tsx`
- AI function: `supabase/functions/generate-chat-script/index.ts`
- Database migration: `supabase/migrations/20260730070000_chat_script_source_and_import.sql`
- Database type change: `WebinarChatScript.source` and `ChatScriptSource` in `src/shared/database.types.ts`

### Script provenance

`webinar_chat_scripts.source` is an enum and must be one of:

- `manual` — typed by the account user.
- `imported` — copied from a real finished live chat.
- `ai` — generated by the AI Edge Function.

### Important behavior and limitations

- **Import latest live chat** correctly fails with “No finished live session found to import from” until a live session has started and ended. This is expected, not a UI error.
- A scenario starts when the attendee opens the webinar room, rather than being synchronized to recorded-video playback. Playback synchronization is not implemented yet.
- AI generation uses `gpt-4o-mini` and requires `OPENAI_API_KEY` in the Supabase Edge Function environment.
- AI generation from recordings or arbitrary uploaded audio/video is **not implemented**. It needs an upload/transcription/job pipeline and a language selection step.

## Funnel editor — latest local changes, not yet pushed

The visual funnel editor supports the Registration, Waiting room and Webinar room pages.

### Layout and responsive work completed locally

The original editor compressed three columns into small screens. It was redesigned with a Scorelt-style workspace:

- Desktop: independently scrollable **Add block**, canvas, and **Block settings** panels.
- Tablet/mobile: the block palette and settings open in their own side panels; the canvas remains usable.
- Explicit desktop/mobile preview switcher changes the canvas width.
- A selected block has a visible outline and opens settings automatically on smaller screens.

### Palette overflow fixed

The old palette rendered icon names such as `Sparkles` and `FormInput` as text, which caused labels to overflow their button/card boundaries. It now:

- Renders actual Lucide icons.
- Uses a responsive grid: one column in the desktop sidebar, two columns where space permits in mobile panels.
- Truncates labels rather than allowing overflow.

### Two blocks in one row (Scorelt lanes/columns concept)

A minimal two-column version of Scorelt’s `lanes` layout is now included:

- Select any block, then choose **Block width** in the settings panel.
- `Full row` is the default.
- `Half row` stores `settings.column_span = 6`.
- Consecutive half-width blocks are displayed side by side on desktop.
- On mobile, every block stacks vertically.
- The name of the corresponding Scorelt concept is **lanes** (or columns/row layout), not a special standalone content block.

## Live chat moderation — not implemented yet

The current system already has soft deletion for individual messages, but the requested streamlined moderation panel and per-webinar user ban workflow have not been built.

Required behavior:

- Host/admin can delete a message from normal webinar chat.
- Host/admin can ban an attendee for one specific webinar.
- A banned attendee cannot send new messages.
- Their old messages are hidden from attendees.
- Moderators can see ban status and unban them from a moderation list.

Existing foundation:

- Soft-delete migration: `supabase/migrations/20260729120000_chat_moderation.sql`
- Public chat API: `src/features/webinars/api/public.ts`
- Webinar room: `src/features/webinars/pages/WebinarRoomPage.tsx`
